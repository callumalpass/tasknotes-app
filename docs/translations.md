# Translation pilot

This branch pilots Lingui 6.9 in the **Collection panel of Settings**, not an application-wide migration. The remaining UI is intentionally English. Data names, paths and authority-provided diagnostic messages are not translated. The mdbase provider-neutral repository boundary is unchanged.

Ordinary release UI remains English. In development or an `e2e` build, open `more?demo=12&i18n-pilot=fr` for the French panel, or `i18n-pilot=en` for English. The disposable demo requires no real collection or account; local browser tests block non-loopback traffic. The parameter is ignored in normal production builds.

## Source and local authoring

- `src/app/collection-settings.tsx` contains English source messages in Lingui React macros.
- `lingui.config.ts` limits extraction to that panel and a test-only rich-text fixture.
- `src/i18n/locales/{en,fr}/messages.po` are the reviewable catalogues. All 15 French entries were authored locally, without a hosted translation service.
- Source text plus semantic `context` determines a generated ID. Source/context changes create a new ID, so old translations cannot silently remain current.
- Translator comments and glossary changes do **not** change IDs. They require linguistic review; extraction/compilation cannot prove translation quality.
- `src/i18n/locales/{en,fr}/messages.json` are deterministic, committed ICU data generated by `compileNamespace: "json"`. They contain arrays/strings, not executable message functions.

```bash
pnpm i18n:extract
# Local agent translates/reviews the French PO entries; inspect the source and glossary.
pnpm i18n:check
pnpm test:release
pnpm test
pnpm typecheck
pnpm lint
pnpm build:e2e
```

`i18n:check` checks extraction sync, missing translations **before fallback**, strict compilation, generated IDs, and source/target ICU argument and numeric React-tag contracts. The generated JSON is compiler-owned, not Prettier-owned. CI also rejects diffs in committed compiled catalogues. CI never calls an AI provider.

## Runtime and representative checks

A scoped `I18nProvider` keeps the experiment out of unrelated screens. English is loaded synchronously; missing target entries merge with English, unsupported locales select English, and there are no language downloads or network-dependent startup steps in this pilot. Neither PO nor downloaded JavaScript is evaluated at runtime. The JSON data is currently bundled; R2 delivery is a later, separately versioned format/loader decision, not a reuse of the plugin's legacy string-pack schema.

The panel tests interpolation, French CLDR plural categories (including zero), translated accessible button names and disclosure state. A fixture tests a translated link while keeping its source-controlled destination, and confirms interpolated HTML is text, not markup. Node tests validate actual committed generated IDs and reject parameter renaming, missing parameters, translator HTML and broken tag placeholders.

```bash
# Fresh browser contexts, in-memory demo, external traffic blocked.
# Pick a free explicit local port rather than reusing another instance.
PLAYWRIGHT_SKIP_BROWSER_GC=1 pnpm exec playwright install chromium
TASKNOTES_DEV_PORT=18573 \
PLAYWRIGHT_BASE_URL=http://127.0.0.1:18573 \
PLAYWRIGHT_WEB_SERVER_COMMAND='pnpm dev:e2e' \
pnpm exec playwright test e2e/i18n-pilot.spec.ts
```

Desktop and Pixel 7 browser-mode English/French tests exercise visible controls, refresh, disclosure and Axe checks. This is web acceptance, not physical-device testing or a claim that collections are available offline. Collection edits still require the authoritative mdbase connection.
